Routing outcomes matter more than raw accuracy. A message routed to the **wrong team** is costly (it sits with people who won't act on it); one sent to **Unsorted** is safe (the GM sorts it in one click). Every complaint must reach the GM.

## How to read this

- **The keyword score is in-sample and optimistic.** The word lists were written after reading these 60 messages, so they partly memorise this set; on new messages expect noticeably lower accuracy. The model's prompt contains none of these messages, so its score is the fairer estimate. A larger held-out set of real enquiries is the first thing to add in production.
- **Why the keyword rules stay, and what was cut.** An earlier version raised or lowered the model's confidence depending on whether the keyword rules agreed. On this set that changed no routing, so it was removed: the model's own confidence now decides Unsorted. The rules keep two cheap jobs where mistakes are expensive: answering when every model is down, and alerting the GM about any complaint a model misses. Compare the 'alone' and '+ keyword rules' rows to see what they add.
- The keyword rules don't extract dates or months (blank by design); the model does. Staff can correct any extracted field, and the draft's quote is re-priced from the rate table when they do.
- The keyword rules always run, as a cross-check and as the fallback when the model is unavailable, so the first row is the floor the system never drops below.
- A complaint seen by **either** classifier alerts the GM; that is why complaint recall can exceed either classifier's accuracy on its own.
- Prices never come from the model; drafts get them from the rate table, so classification mistakes can't produce a wrong price.
